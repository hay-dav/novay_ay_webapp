# Видео-трансляции

## Архитектура

Трансляции работают через self-hosted LiveKit SFU:

1. Администратор создает эфир через `POST /api/v1/live-streams/start`.
2. Laravel создает уникальную комнату `novaya-ya-live-{id}`.
3. `POST /api/v1/live-streams/{id}/token` возвращает URL LiveKit и подписанный JWT.
4. Ведущий публикует один поток камеры и микрофона в LiveKit.
5. Зрители получают только право подписки. LiveKit распределяет поток и адаптирует качество.
6. Запись создается в браузере ведущего и после завершения загружается в раздел тренировок.

Старый P2P mesh и REST-сигналинг offer/answer удалены. Устройство ведущего больше не отправляет отдельный видеопоток каждому зрителю.

## Параметры качества

- основное качество: 1280×720, 30 FPS;
- максимальный видеобитрейт: 2,5 Мбит/с;
- аудио Opus: до 96 Кбит/с;
- simulcast-слои: 180p, 360p и 720p;
- `adaptiveStream` выбирает подходящий слой для каждого зрителя;
- `dynacast` не кодирует слои, на которые никто не подписан.

## Локальная среда

Docker Compose запускает:

- LiveKit: `ws://localhost:7880`;
- метрики LiveKit: `http://localhost:6789/metrics` (доступны только локально);
- WebRTC TCP fallback: `localhost:7881`;
- WebRTC UDP: `50000-50100`;
- Coturn: `localhost:3478`;
- TURN relay UDP: `49160-49200`.

Локальные ключи предназначены только для разработки:

```env
LIVEKIT_API_KEY=devkey
LIVEKIT_API_SECRET=dev-secret-change-before-production-123456
LIVEKIT_PUBLIC_URL=ws://localhost:7880
```

## Production

Перед публикацией:

1. Разместите LiveKit на отдельном сервере в российском дата-центре.
2. Задайте случайные `LIVEKIT_API_KEY` и `LIVEKIT_API_SECRET` одновременно в Laravel и LiveKit.
3. Замените `LIVEKIT_PUBLIC_URL` на `wss://live.example.ru`.
4. В `infra/livekit/livekit.yaml` включите `use_external_ip: true`.
5. В `infra/livekit/livekit.yaml` замените TURN host на публичный IP или `turn.example.ru`.
6. В `infra/coturn/turnserver.conf` замените realm, логин и пароль, добавьте `external-ip`.
7. Настройте TLS для LiveKit и TURN через отдельные домены.
8. Откройте только необходимые TCP/UDP-порты в firewall.
9. Подключите Prometheus к порту 6789 и настройте оповещения по CPU, packet loss, RTT и числу участников.
10. Выполните нагрузочный тест минимум на 40–50 зрителей.

Для 30 зрителей рекомендуется отдельная машина LiveKit с 4–8 vCPU, 8–16 ГБ RAM и гарантированным каналом не менее 100 Мбит/с. Для 720p при 2,5 Мбит/с серверу потребуется примерно 75 Мбит/с исходящего трафика без учета протокольного запаса, поэтому предпочтителен порт 1 Гбит/с.

## Ограничения записи

Доставка эфира выполняется SFU и не зависит от записи. Сама запись пока формируется `MediaRecorder` в браузере ведущего. Если вкладка или устройство ведущего аварийно завершит работу, запись может не сохраниться, хотя эфир до момента обрыва будет доставляться зрителям.

Следующий уровень надежности — отдельный LiveKit Egress, сохраняющий запись комнаты непосредственно в S3.
