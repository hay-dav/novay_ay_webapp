# Архитектура проекта

## Цели

«Новая Я» строится как API-first продукт. Web-клиент, будущие iOS/Android приложения и внешние интеграции используют один REST API и единые правила авторизации.

## Модули

- Identity: регистрация, вход, роли, профили клиента и тренера.
- Catalog: программы, курсы, уроки, видео, подкасты и стримы.
- Commerce: покупки, платежи, статусы заказов, webhook-подтверждения.
- Coaching: рацион, замеры, прогресс, задания и заметки тренера.
- Media: загрузка файлов в S3-compatible storage, хранение метаданных.
- Realtime: уведомления, чат, события прогресса и начала стримов.
- Trainer Cabinet: управление курсами, клиентами, рационом, контентом и аналитикой.

## Backend

Laravel разделен на тонкие HTTP-контроллеры, модели домена и сервисы. Контроллеры принимают запросы, валидируют входные данные и делегируют бизнес-операции сервисам. API защищается Laravel Sanctum. Роли хранятся на пользователе и проверяются middleware/policies.

Очереди Redis используются для email, обработки медиа, уведомлений и webhook-задач. Broadcast-события совместимы с Soketi/Pusher-протоколом.

## Video SFU

LiveKit принимает один WebRTC-поток тренера и адаптивно распределяет его зрителям. Coturn обеспечивает подключение пользователей из сложных NAT и корпоративных сетей.

Laravel не передает медиапакеты. Для каждого эфира backend создает имя LiveKit-комнаты и выдает короткоживущий JWT. Ведущий получает право `canPublish`, клиент — только `canSubscribe`.

## Frontend

Vue 3 приложение построено вокруг route-level экранов и Pinia-хранилищ. Axios-клиент централизует токен, ошибки и базовый URL. Интерфейс mobile-first: нижняя навигация на телефонах, боковая панель на широких экранах.

## Мобильная готовность

- REST API не зависит от web-сессий.
- Sanctum token-based режим подходит для мобильных клиентов.
- DTO-ответы стабильны и документируются.
- Медиа отдаются через временные URL.
- Realtime-каналы используют транспорт, совместимый с мобильными SDK.

## Безопасность

- Секреты только в `.env`.
- Пароли хэшируются bcrypt/argon.
- Платежи имеют отдельную модель Payment и idempotency reference.
- Файлы загружаются через backend, валидируются и сохраняются в приватный bucket.
- Доступ к клиентским данным ограничивается ролью и привязкой trainer-client.
